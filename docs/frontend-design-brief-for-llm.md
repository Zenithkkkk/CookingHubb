# Smart CookingHub — Frontend Design Brief

> 用途：把这份文档发给另一位 LLM / 设计师，讨论如何改进网站视觉与信息架构。  
> 基于当前代码实际实现（Node/Express + EJS + 单一 `public/css/style.css`）。  
> 线上示例：`http://8.148.229.49`（也可能仍有旧的 Render 部署）。

---

## 1. 产品是什么

**Smart CookingHub** 是一个多语言社区食谱网站，面向会做饭的用户与学习者。

核心价值：
- 浏览 / 搜索 / 发布食谱
- 用「我的冰箱」里的食材匹配可做的菜
- 按标签发现菜谱
- 点赞、评论（含嵌套回复与评分）、排行榜
- 界面语言：英语 / 德语 / 西班牙语 / 中文
- 部分内容支持机器翻译（菜谱正文、评论）

技术形态：服务端渲染（EJS），不是 React SPA。几乎所有样式集中在一个 CSS 文件。品牌在导航上写作 **「🍳 Smart CookingHub」**。

## 2. 当前视觉语言（设计令牌）

整体是 **暖色、偏餐厅/食谱杂志** 的风格：奶油底 + 陶土橙主色 + 深棕文字 + 衬线标题。

## 3. 全局布局

```
┌──────────────────────────────────────────────┐
│ sticky nav（深棕底 #3b2f2f）                   │
│ 品牌 | 中部链接（排行榜/冰箱/标签/菜谱/…） | 登录区 │
├──────────────────────────────────────────────┤
│ main（max-width 1100px，居中，padding ~2rem） │
│                                              │
├──────────────────────────────────────────────┤
│ footer（顶部分割线 + 版权文案）                 │
└──────────────────────────────────────────────┘
```

### 导航（`views/partials/header.ejs`）

- 桌面：CSS Grid 三列 `品牌 | 中部链接 | 登录/退出`
- 中部链接是半透明白底「药丸」样式
- 登录后额外显示：点赞、个人主页
- 语言下拉：`Germany / Spanish / Chinese / English`（文案是语言名，不是本地化国旗）
- 「联系我们」是独立按钮样式 `.nav-contact-btn`
- 品牌带 emoji 🍳

### 页脚

简单居中版权，无站点地图、无社交链接栏。

### 语言切换体验

切换语言时：先隐藏 `main`，显示全页 skeleton，再跳转 `/language?lang=&next=`。

## 4. 页面与功能块（按用户路径）

### 4.1 菜谱列表 `/recipes`（默认首页）

- `/` 直接重定向到这里，**没有独立落地页/营销首页**（`home.ejs` 存在但未挂路由）
- **搜索栏**：关键词、标签、主食、分类等筛选
- **结果网格**：`.recipe-grid` → `auto-fill, minmax(280px, 1fr)`
- **卡片**：图（约 4:3）+ 标题 + 摘要信息；整卡可点
- Hover：上浮 + 轻微放大 + 橙色阴影
- 搜索提交时可显示 skeleton

### 4.2 菜谱详情 `/recipes/:slug`

功能块自上而下大致为：
1. 大图
2. 标题 / 元信息 / 作者
3. 正文步骤描述（可翻译控件）
4. 「所需食材」区域
5. 标签 chips
6. 点赞
7. 分享（Twitter / Facebook / 微信二维码弹层）
8. 编辑/删除（作者或管理员）
9. 评论区：星级评分、嵌套回复、翻译、删除

动效：详情容器 `.recipe-slide-in` 从右侧滑入（约 0.3s；尊重 `prefers-reduced-motion`）。

### 4.3 新建 / 编辑菜谱

- 表单卡 `.form-card`（约 500px 宽）
- 字段：标题、描述、分类等
- **配料**：textarea +「从描述提取」按钮
- **图片**：双面板——本地上传 / URL；Cropper.js 裁剪

### 4.4 排行榜 `/recipes/leaderboard`

三个 Tab：
- 菜谱（按赞等）
- 贡献者（表格）
- 评分

卡片可带角标：名次 / 赞数 / 评分。

### 4.5 我的冰箱 `/fridge`（需登录）

左右布局（桌面）：
- **左侧 sticky 侧栏**：已选食材 tags，可增删
- **右侧结果**：按匹配度分组  
  - perfect（全匹配）  
  - almost（接近）  
  - inspiration（灵感）  
- 缺料用红色提示

手机端改为单列。

### 4.6 标签页 `/tags`

- 顶部渐变面板 + 标题
- 大量可点选标签芯片（多选，查询逻辑为 OR）
- 查询按钮带 ripple 涟漪
- 结果区可 skeleton
- 有「匹配所选标签中的任意一个」类提示文案

### 4.7 点赞页 `/recipes/liked`

- 用户点赞的菜谱列表
- 可切换个人主页上点赞列表的公开/隐藏（toggle）

### 4.8 个人主页 `/profile/:username`

- 头像、简介
- 该用户发布的菜谱
- （若公开）其点赞列表

### 4.9 编辑资料 `/profile/edit/me`

- 表单 + 头像 Cropper 裁剪上传

### 4.10 登录 / 注册

- 居中窄表单卡
- 注册支持邮箱或手机（国码 + 号码并排）

### 4.11 联系我们 `/contact`

- 多语言联系说明块
- 表单
- 微信 / Instagram 等二维码展示区

### 4.12 管理后台 `/admin/users`

- 用户表格
- 角色徽章、切换 admin

### 4.13 404

- 简单标题 + 说明 + 回菜谱列表链接

## 5. 组件模式清单

| 模式 | 表现 |
|------|------|
| 主按钮 | `.btn-primary` 橙色实心 |
| 次按钮 | `.btn-secondary` 描边/浅底 |
| 危险按钮 | `.btn-danger` |
| 食谱卡 | `.recipe-card` + 图片 + 文字 |
| 药丸标签 | `.recipe-tag` / `.tag-chip`，圆角 ~20px |
| 表单卡 | `.form-card`，白/浅表面，圆角 8px |
| 模态 | 居中对话框；手机为底部 sheet |
| Skeleton | 灰色块 + shimmer 扫光 |
| 星级 | 金色星；输入用反向 flex + CSS |
| 评论 | 左边橙色竖条；回复缩进 + 浅棕左边框 |
| 导航链接 | 深底上的半透明白药丸 |

## 6. 动效

1. 菜谱卡 hover：上移 + scale + 橙影  
2. 详情页进入：右滑入  
3. Skeleton shimmer（约 1.3s 循环）  
4. 标签查询按钮 ripple  
5. 标签页标题切换淡入淡出  
6. 多数控件 0.15–0.25s 颜色过渡  

整体动效偏少、偏功能反馈，没有品牌级开场动画或滚动叙事。

## 7. 响应式

| 断点 | 主要变化 |
|------|----------|
| ≤1200px | 导航字号/间距收紧 |
| ≤768px | 导航折行；冰箱单列；联系单列；模态变底栏 |
| ≤640px | 搜索按钮更易全宽；标签芯片略缩小 |
| ≤430px | 更紧凑导航（小屏手机） |

内容最大宽约 1100px；卡片网格最小约 280px。

## 8. 已知设计/体验问题（供改进时参考）

这些问题来自当前实现，不是必须全改，但对「如何改进设计」很有用：

1. **没有真正的 Landing / Hero**：进入即列表，品牌叙事弱。  
2. **导航信息密度高**：排行榜、冰箱、标签、菜谱、点赞、主页、语言、联系、登录挤在一行，小屏更挤。  
3. **视觉语言偏「通用美食博客模板」**：奶油底 + 陶土橙 + Playfair，辨识度一般。  
4. **Emoji 品牌**：🍳 放在品牌名旁，不够精致。  
5. **首页/空状态/引导** 较弱：新用户不知先用冰箱还是先逛标签。  
6. **页脚极简**：缺少次要导航与信任信息。  
7. **语言下拉文案** 不统一（Germany vs German 等）。  
8. **Dancing Script 已加载未用**；书法字体可能缺失 → 点赞页排版不可靠。  
9. **卡片依赖 hover 动效**：触屏设备反馈弱。  
10. **标签页内联大量 JS**，样式与行为耦合，后续改视觉成本高。  
11. **管理后台** 偏「能用的表格」，与前台品牌感不一致。  
12. **分享区** 多色第三方按钮并列，略杂。

## 9. 内容与品牌约束（改进时请遵守）

- 产品名：**Smart CookingHub**（可讨论是否缩短为 CookingHub）  
- 必须继续支持 **四语 UI**（en/de/es/zh）  
- 核心功能不能砍掉讨论范围外的：菜谱 CRUD、冰箱匹配、标签、评论评分、排行榜、点赞、个人主页、联系页  
- 技术约束：当前是 **EJS + 单 CSS 文件**；改进方案最好能落到「改 CSS / 改布局 partial / 加简单 landing」，而不是假设立刻重写成 React  
- 图片多为用户上传 + Cloudinary；默认图存在

## 10. 希望另一位 LLM 输出什么

请基于以上现状，给出**可执行的设计改进方案**，优先包括：

1. **整体视觉方向**：保留暖色美食感，还是转向更现代/更品牌化的方向？（给 1–2 个明确方向，含色板与字体建议）  
2. **信息架构**：导航如何重组？要不要独立首页 Hero？冰箱/标签如何在首页露出？  
3. **关键页面线框级描述**：首页、菜谱列表、详情、冰箱（桌面+手机）  
4. **组件规范**：按钮、卡片、标签、表单、空状态的统一规则  
5. **动效建议**：2–3 个有存在感但不吵的动效  
6. **避免**：纯紫渐变 SaaS 风、过度卡片化仪表盘、无意义的大面积毛玻璃  

请用中文回答；方案请区分「低成本只改 CSS」与「需要改 EJS 结构」两档。
